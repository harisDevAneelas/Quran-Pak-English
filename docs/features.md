# How the app works

One block per area. Update the block when a shipped `specs/` change alters that behavior.

## Reader

The user scrolls one vertical mushaf: a surah header, then each ayah. The top bar shows the current surah and ayah; tapping it opens surah and ayah wheels (`surah_ayah_picker_sheet.dart`). That top-slide picker has a centered title (no Done in the header), a bottom Done, and paints its grey header under the status bar while open. Surah names are the left wheel and ayahs are the right wheel. The menu button is on the left and opens the left drawer. The hub grid icon is on the right. That same drawer is on the hub and on every pushed screen (collections, search, bookmarks, settings lists, and Translation and tafsir). Surah/para jumps from it return to the mushaf. The bottom bar has Recitation order on the left, previous / play / next in the center, and ayah repeat on the right. Daily recitation plan stays on the hub tile and the drawer gear — not on this bar. That bar is painted over the mushaf (it does not resize the list). It stays sticky while scrolling. The top bar stays put.

Previous, play, and next drive audio. If audio is already active, previous and next skip ayahs. If it is not, they start playback at the neighbor of the top visible ayah. Play toggles pause when a file is loaded. Repeat cycles on the bottom-bar button; when the same ayah starts again for a repeat, that button jumps up then settles like a bouncing ball on the way down. The mushaf follows each ayah as it starts only while that ayah is still on the reader and no other full-screen page is open. Scrolling the playing ayah off screen, or opening another page, pauses follow and shows a floating orange chip with a close control on the left, the Arabic surah name and `Ayah …` in the center, and play / pause on the right. It sits with a gap above the transport — or above the bottom safe area when the transport is hidden or the user is on another page that has no bottom chrome. On Today's recitation it sits above the completion question while that bar is showing, the same way it sits above the reader transport, and the last ayah stays visible above the chip. The chip stays on the page and the sidebar covers it (it does not hide, and it does not paint over Menu). It does not appear on Daily recitation plan (kind picker and setup). Tapping the label returns to the ayah that is playing and follow resumes. Play / pause matches the transport. Close stops the audio. Pause keeps the chip; stop hides it.

Tapping an ayah opens six actions (`ayah_actions_popup.dart`): Recitation plays that ayah, Bookmarks saves it, Word by word opens word-by-word, About this surah opens surah facts, Share copies the surah name and ayah number, Translation and tafsir opens that ayah with every translation then the tafsir columns. The bottom-left queue icon opens Recitation order; play is tap-only. That dialog has no Close button; tapping outside dismisses it, and the card follows light or dark.

Entry: `lib/reader/quran_reader_screen.dart`, `lib/reader/quran_reader_controller.dart`, `lib/reader/widgets/quran_ayah_widget.dart`, `lib/reader/widgets/mushaf_pinch_zoom.dart`, `lib/core/mushaf_layout.dart`.

Data: splash keeps the English phone-portrait `splash_screen.png` on screen (Flutter paints it stretched full-bleed; Android 12+ OS splash cannot) while it loads a small window of `quran.colored.json` around the opening position (Fatiha on cold start, or the saved ayah), then shows the reader. Namaz alerts are rescheduled after that first reader frame. The full file finishes in the background into one process-wide cache. On IO the parse runs in an isolate; on web it runs on the UI isolate. Hub collections and today's recitation reuse that cache. The reader absorbs ayahs into one map. List indices stay fixed, so filling later rows does not jump the scroll. A row that is not in the map yet is a light placeholder. The surah header is the Arabic name between painted ornate brackets with side flourishes, on a soft center wash that follows light or dark (page-colored sides, no card border); bismillah sits beneath it. Header bismillah is plain words from `quran.metadata.json`, hidden on surah 9, with no end-of-ayah digit.

Ayah rows use HarfBuzz justification (`third_party/arabic_text_justification`) and precomputed Tajweed ranges. While the mushaf is still, a new line is shaped immediately. During a fling, lines ahead of the viewport are shaped a few per frame (HarfBuzz queue + deeper ayah prefetch; larger outline cache), and a line that is not ready yet keeps its final height until its outlines arrive. The para-name words at the start of each para (one to three) are drawn a little larger and heavier. Those starts come from `Quran.ParaStart`, so para 4 opens on 3:92 (`لَنْ تَنَالُوا`) and the para list jumps there. Para 1 still ranges from Fatiha, but its name الم is drawn on Baqarah 2:1, not on Fatiha. After the ayah digit, the last ayah of a `ParaRubaStart` quarter shows ۞. The last ayah of a `RukuStart` keeps that same line packing and draws a smaller orange ع just above the ayah oval (`MushafDivisions`, warmed at bootstrap). Tapping it on the main reader opens a card titled Ruku details, with the surah, the para, ruku in the para, ruku in the surah, and the ayah count. The card uses the scaffold background and theme ink (white in dark mode), with the label on the left and the value, including the integers, on the right. That tap does not open the ayah actions. Font size is 18–56, default 40, from the Text size sheet; the slider previews locally while dragging and commits when the finger lifts so the mushaf does not reshape on every tick. On the main mushaf, Today's recitation, verse collections (Ayaat-e-shifa, Ruqyah Shariah, and the other hub duas), word-by-word, and Translation and tafsir, a two-finger pinch changes text size live (text reflows; half-point steps, at most once per frame), within the same 18–56 range (`MushafPinchZoom`). Scroll locks while pinching, and the ayah under the fingers stays anchored as size changes. Read in the dark sets light or dark (the stored default before that toggle is system). Tajweed colors toggles paint only. `customBackground` is applied when present in saved settings; no screen writes it. None of these reload the JSON. Hub tiles, daily-plan cards, ayah actions, tilawat-order buttons, app-bar titles, and related overlays take sizes from `lib/core/app_dimens.dart`, scale them to the screen's shortest side, and shrink labels to the available box so English is not clipped or ellipsized on narrow phones; landscape grids scroll when they do not fit. Chrome is left to right. Every top bar is left to right. The menu button stays on the left, the same corner as the main screen. Back sits on the right of every header. The title stays centered. Arabic mushaf lines, surah banners, header bismillah, and ayah markers stay right to left.

## Tajweed and fonts

Tajweed on: each word is colored from the JSON highlight mask. Tajweed off: the same words paint in plain ink. The parser validates highlight indexes, writes a color mask, and merges adjacent runs of the same color. That work happens at parse time.

Entry: `lib/data/tajweed_parser.dart`, `lib/core/quran_font.dart`.

Word-by-word Arabic uses the IndoPak face `AlQuranIndoPak` as a plain `Text`, not the justification shaper, and with no Tajweed tint. The mushaf face stays KFGQPC. Boxes in one row share the height of the tallest box. Private-use ruku ayn marks are not shown.

## Audio

Play starts at the chosen ayah and continues through the mushaf. The reader follows that ayah until the user leaves it (scroll or another page); the playing-ayah chip then names the verse, can pause or resume, and jumps back on tap (see Reader). As soon as that ayah starts, the next five ayahs are preloaded in mushaf order (N+1 first). On IO they are stored as files under the OS temp `ayah_audio` folder; on web the browser audio element preloads them (the CDN has no CORS for `http.get`). Cached files older than two months are deleted, and if the folder exceeds 300 MB the oldest files are removed until it is under that size (maintenance runs when the cache is opened and after each new download). Advancing waits for a preload already in flight so a slow network does not stall between verses. The ayah being heard still starts immediately if it is not cached yet. Repeat cycles 1 → 2 → 3 → unlimited, then back to 1. Each cycle is how many times that ayah's audio finishes before advancing; a same-ayah repeat seeks and replays the already-loaded file without downloading again. Repeat 1 advances to the next ayah once — duplicate `completed` events from the player do not skip a verse. The order dialog is تلاوت کی ترتیب: recitation only, translation only, recitation then translation, or translation then recitation.

The user picks a reciter (default `afasy`, English names, portraits in `assets/reciters/`). Spoken translation is a separate toggle and language list (default English) with English language names and circular country flags in `assets/flags/` (`audio_language_list_screen.dart`, same avatar size as reciters). Order is recitation only, translation only, recitation then translation, or translation then recitation. Turning spoken translation on selects recitation-then-translation if the order was recitation only. Turning it off forces recitation only. On-screen translation text does not follow that audio toggle. Choosing صرف ترجمہ (or a mixed order) still shows the translation under each ayah.

Entry: `lib/reader/ayah_audio_controller.dart`, `lib/reader/ayah_audio_handler.dart`, `lib/data/ayah_audio_cache.dart`, `lib/data/ayah_audio_cache_policy.dart`, `lib/data/reciter_catalog.dart`, `lib/data/audio_language_catalog.dart`, `lib/data/tilawat_order.dart`, `lib/data/ayah_repeat_mode.dart`.

CDN folders that 404 are omitted (`farhat`, `itani`, `sowaid`, `temp`). Turkish whole-surah audio is omitted because it has no per-ayah files. A failed load sets `failed` on the controller; it does not skip ahead on its own.

بیک گراؤنڈ میں تلاوت (drawer toggle, migrated from فون لاک) lets tilawat continue when the phone is locked or the app is backgrounded. The system media notification / lock screen shows play, pause, previous, and next. When the toggle is off, locking or leaving the app pauses audio. Web stays in-tab only (no OS media chrome). Android 10+ and iOS use `audio_service` + a music `audio_session`; the screen is no longer kept awake for this setting.

## Translations

Under each ayah, zero or more English translations from the drawer multi-select. The picker lists full translator names only (no short side labels), has no drawer of its own, and saves with a gold Save chip in the app bar. The user may select none, one, or several. Default is `SaheehInternational`. A saved Urdu translator id falls back to that default. Ibn Abbas (`IbneAbbas`) and Jalalayn (`Jalalyn`) are the tafsir section. Transliteration and phonetic are extra rows in the same picker, not tafsir. Every catalog id is left to right. Show translation shows or hides the text only; it does not change spoken translation, and spoken translation does not hide or show that text. Saving an empty selection hides on-screen text; picking any translator turns the text back on. With one translator selected, the ayah shows the text only (no name credit). With two or more, each shown line ends with that translator's full name credit.

Entry: `lib/data/translation_catalog.dart`, `lib/data/translation_repository.dart`.

Data: column per translator on the SQLite `Quran` table, keyed by `SuraNum` and `AyaNum` after `DbAyah` conversion. Catalog ids must be real column names.

## Word by word

Opened from the ayah action Word by word. A second continuous list, same surah/ayah scrolling as the main reader, starting at the tapped ayah. The orange top bar shows the current surah name and ayah the same way as the main reader; tapping it opens the same surah + ayah wheels and jumps on this list. Each surah uses the same ornate header as the main reader, with bismillah under the name (none on surah 9). Each ayah still has its in-list Arabic name and `Ayah …` label above the word boxes. Each cell is one database pair: Arabic above its English gloss. The gloss is left to right. The Arabic word row stays right to left. Column count follows font size and available width so IndoPak Arabic is not mid-cut on narrow phones. It has its own font-size sheet. Closing it returns the ayah the user was on.

Entry: `lib/reader/screens/word_by_word_screen.dart`, `lib/data/word_by_word_repository.dart`.

Glosses come from `Quran.words` in `english_db.sqlite`, stored as `[arabic:english]` pairs and cached per surah. Nineteen ayahs have an empty cell and show no word boxes. Fatiha uses app ayah numbers (6 ayahs).

## Profiles, bookmarks, position

Profiles are device-local. The first one is created as `پروفائل` if none exist. New profiles default to light (white) theme, not system. The profile screen shows the active name with on-page نام تبدیل کریں and پروفائل ختم کریں, a chip switcher at the top, and grouped cards: today’s recitation range, daily-plan setup, tilawat reminder, tilawat order, عصر کا وقت dropdown (فقہ: حنفی/شافعی; same expand pattern as تلاوت کی ترتیب; namaz calculation stays کراچی), azaan voice for namaz notifications, reciter, spoken and on-screen translation, dark mode, Tajweed, text size, background tilawat, and reset to defaults. Reciter, spoken-translation, and azaan pickers select in place (Save to leave); each row’s preview plays Fatiha’s 2nd verse (`001002`) or the azaan asset. Azaan has an on/off toggle like Show translation — off keeps namaz alerts but uses the default system sound. آج کی تلاوت is an orange-gradient action button matching the app bar (range still shown on it, right-aligned). Preference rows sit in white grouped cards with orange icons, hairline dividers, and a light shadow. Expanding تلاوت کی ترتیب tints that nested list a shade darker so it reads as part of the row. Chips, dialogs, and footer actions keep the orange/gold chrome, except پروفائل ختم کریں which is a solid red danger button. The app bar has نیا پروفائل instead of the drawer. Switching or creating stays on that page. The drawer still has the same preference rows. Leaving that screen, or deleting the active profile, returns a reading position so the reader can jump.

Entry: `lib/reader/profile_manager.dart`, `lib/app.dart` (`switchProfile`, `deleteProfile`), `lib/reader/reading_position_store.dart`, `lib/reader/bookmark_store.dart`, `lib/reader/index_bookmark_store.dart`, `lib/reader/reader_settings.dart`.

Position is surah + ayah. It autosaves as the visible ayah changes. Bookmarking an ayah also writes that pair as the reading position, and inserts `surah:ayah` at the front of the bookmark list. Whole-surah and whole-para bookmarks from the index grids are stored separately (`IndexBookmarkStore`) per profile. آج کی تلاوت keeps a separate position store. Profile-scoped stores (position, bookmarks, index bookmarks, daily plan, pins, tilawat position, learned notify) rebind in `QuranApp` when the active profile changes. بیک گراؤنڈ میں تلاوت is the background-tilawat preference (see Audio).

## Hub, daily plan, collections

The hub grid and the drawer both open these. Screens opened from the hub (today's recitation, Ayaat-e-shifa, the forty Rabbana, Manzil, Ruqyah Shariah, daily-plan setup, Surah list, Para list) stay above the hub, so Back returns to the hub. A surah or para chosen from those lists still closes every screen above the mushaf and jumps in the reader. Hub Surah list and Para list push searchable two-column grid screens (`SurahGridScreen` / `ParaGridScreen`) with an orange app bar and a live filter field; the drawer rows with the same titles open those same screens. English names on each card shrink to fit the tile (`ScreenFitText`, up to two lines). Each grid card has a star: starring a surah or para bookmarks it for the profile. Bookmarked items also appear as a strip under the search field when the user returns to that grid. Starring a surah also pins it into Quick list and shows it as a hub tile (paras are bookmarked only — they do not get hub tiles). Unstar on the grid, or delete on Bookmarks, clears that bookmark and (for a surah) also clears the pin / hub tile. In Quick list, unchecking a row only removes the hub tile (star stays); tapping the star button there clears the bookmark and removes it from the quick list / hub. Bookmarked surahs outside the eight occasion rows still appear in that sheet. Surah search matches number, Arabic name, English name, meaning, and `Sura.SimpleEngName` aliases with fuzzy romanization (kahaf/kahf, yaseen/yasin) and Arabic letter folding; hits sort best-first. Para search uses the same matcher on number plus `Juz` Eng / Arabic / Urdu names. Tapping a surah jumps to that surah's header; tapping a para jumps to that para's first ayah. The reader menu icon is 30px. The hub's list icon opens the same `ReaderMenuDrawer` (dark chrome, white row icons, a light wash on Today's recitation, and a white close control in the header). Left-side controls share one column. The reset row is Reset to defaults. Switch rows keep a reserved slot and the same vertical padding as the other items so labels and toggles do not overlap on a narrow iPhone. The top-bar still uses the smaller top-slide surah+ayah picker. The drawer still has today's-recitation and daily-plan rows at the top, Surah list and Para list destinations, search, bookmarks, profile, reciter, spoken translation, on-screen translation, dark mode, Tajweed, share, text size, Background recitation, and Reset to defaults (confirm, then factory defaults for reader prefs on the active profile; bookmarks, position, and daily plan stay). The hub adds the timed-surah shortcut, Ayaat-e-shifa, and the forty Rabbana. Share copies a fixed English sentence to the clipboard.

The hub shows a namaz bar (current prayer, Islamic/Hijri date, and end time) from device لوکیشن using کراچی calculation and the active profile’s عصر فقہ (حنفی/شافعی on the profile screen). Fajr’s window ends at طلوع آفتاب (sunrise from `adhan`), not at ظہر; between sunrise and ظہر the bar shows اگلی نماز ظہر with its start. The day card lists طلوع آفتاب after فجر. Times always use the device’s لوکیشن. On the first app open only, if لوکیشن is not allowed, an Urdu consent dialog asks whether to allow it for namaz times (tap outside dismisses); later opens do not re-ask. After allow (or a successful hub-bar refresh), a GPS fix is taken at most about twice a day and cached; hub times and the day’s namaz / prayer-anchored surah notifications are rescheduled immediately from that cache (no continuous لوکیشن). Hub bar tap can still force a refresh. Tapping the bar opens a blurred card (same family as رکوع کی معلومات) with that day’s فجر–عشاء times. Grid tile **Quick list** sits beside Today's recitation and opens the pin sheet for the eight occasion surahs (Muzammil, Rahman, Yasin, Waqiah, Mulk, Sajdah, Kahf, Dukhan) plus any other bookmarked surahs. Any surah 1–114 may be pinned (including via grid star). Unchecking a row hides the hub tile but keeps the star; the star button on a bookmarked row unstars and unpins. Only currently pinned surahs show as hub tiles after Quick list (not paras). Timed display windows stay clock-based: Ya-Sin 6:00–12:00; Al-Waqi'ah, Al-Mulk, and As-Sajdah 19:00–3:00; Friday 6:00–19:00 Al-Kahf; Thursday 20:00–3:00 Ad-Dukhan. آج کی تلاوت and timed tiles are highlighted.

آج کی تلاوت is optional-portion: with no ترتیب for the profile store, it is the full Arabic mushaf (Tajweed/ayah paint like the reader, no audio/translation chrome) with its own resume position (`TilawatPositionStore`), separate from the main mushaf. Resume uses the same pattern as the main reader: `initialScrollIndex` from the saved ayah, top-visible tracking, debounce while scrolling, flush on scroll end / leave. A full-width black question bar at the top asks روزانہ کی تلاوت کی ترتیب سیٹ کریں۔ with a centered ترتیب بنائیں button, at most once per local day per profile and only while no plan is set; later opens that day skip it. It hides after a few seconds or when scrolling up. Cold start still opens the main mushaf.

When ترتیب is set, آج کی تلاوت loads only today’s window from `DailyRangeResolver` (opens at the top of that portion, not full-mushaf resume). Near the end an orange bottom bar asks کیا آپ نے آج کی تلاوت مکمل کر لی؟ (same family as the reader transport; the playing-ayah chip lifts above it). Yes advances the plan start via `nextStartAfter`, stamps `markCompletedToday`, and opens the completion card: اَلْحَمْدُ لِلّٰهِ, مزید آج کی تلاوت, hub-style آج کی سورتیں tiles (مزمل / رحمان plus timed `RecommendedSurahResolver.resolveMany`), and صدق اللہ العظیم. Tapping a surah jumps to it on the main mushaf. No re-offers while still at the end. Returning from ترتیب setup reloads so the screen switches between full and portion mode.

Daily plan setup remains separate: pick رکوع، آیات، پارے، or صفحات, then amount, start, and reminder. The kind-picker has no profile chips; the amount/start/reminder screen still shows horizontal profile chips (plus نیا پروفائل) so the user can edit another profile’s plan — or create one — without switching the app’s active profile. After save, an informative confirmation names the next fire time, and the user is taken to آج کی تلاوت. The daily-plan reminder tap also opens آج کی تلاوت. Plan range math lives in `DailyRangeResolver` for profile labels and for the portion list when a plan exists.

Surah notifications: یاسین defaults to Fajr+30 (clamped 4:00–7:30); واقعہ Maghrib+30; ملک Isha+30 (evening clamp: that prayer’s start → next day 02:00). Opening a surah from its notification stores the open time and schedules the next day two minutes earlier within clamps. کہف (Friday 6:00) and دخان (Thursday 20:00) keep fixed edges. No سجدہ notify. Namaz-start notifications fire for فجر، ظہر، عصر، مغرب، عشاء and play the profile’s chosen azaan (default Muhammad Ramadan Saad; three bundled voices). Surah and daily-plan reminders keep the default system sound. Tapping a surah reminder opens that surah; namaz start opens the hub; daily-plan reminder opens آج کی تلاوت. Web does not schedule reminders.

Entry: `lib/reader/screens/hub_menu_screen.dart`, `lib/reader/screens/surah_grid_screen.dart`, `lib/reader/screens/para_grid_screen.dart`, `lib/reader/widgets/index_grid_card.dart`, `lib/data/recommended_surah.dart`, `lib/reader/pinned_surah_store.dart`, `lib/reader/index_bookmark_store.dart`, `lib/reader/prayer_time_service.dart`, `lib/reader/daily_plan.dart`, `lib/reader/daily_range.dart`, `lib/data/mushaf_divisions.dart`, `lib/reader/screens/todays_recitation_screen.dart`, `lib/reader/tilawat_position_store.dart`, `lib/reader/learned_notify_store.dart`, `lib/reader/app_notification_scheduler.dart`, `lib/reader/notification_route.dart`, `lib/data/verse_collections.dart`, `lib/data/verse_collection_repository.dart`, `lib/reader/screens/verse_collection_screen.dart`.

## Search, about, bookmarks list

Drawer search is Arabic mushaf-word search only (not the surah/para name grids). It indexes every word from the full `quran.colored.json` cache (`ArabicVerseSearch` / `loadFull`), matches with harakat stripped, and shows up to 100 hits with the Arabic surah name and ayah. Tapping a hit closes every screen above the mushaf (hub, collections, and search) and jumps to that ayah on the main reader. Surah and para name browsing with multilingual filter lives on Surah list / Para list (see Hub). The surah-about screen reads the name, English title, revelation, page, para, and English introduction from `Sura`, and can pop a jump request. The bookmarks screen lists the active profile's starred surahs, starred paras, and ayah bookmarks in sections (Surah / Para / Ayahs); surah and para rows keep mark order (first bookmarked first), not number order — same order as the strip under the grid search field. Deleting a surah row also clears its Quick list pin. Tapping a surah opens its header; a para opens its start ayah; an ayah opens that verse. Its empty state uses theme ink so it stays readable in dark mode. Sidebar, hub quick-list, and menu surah titles use `Sura.EngName` (Arabic mushaf banners stay `ArabicName`). Para titles come from `Juz.EngName`. Text size uses the classic Aa format-size icon; dragging the size slider updates the label immediately and applies the mushaf size on release. Dark mode body text defaults to white via `AppTheme`.

Entry: `lib/data/arabic_verse_search.dart`, `lib/reader/screens/surah_search_screen.dart`, `lib/reader/widgets/search_query_field.dart`, `lib/reader/screens/surah_about_screen.dart`, `lib/reader/screens/bookmarks_screen.dart`, `lib/reader/index_bookmark_store.dart`.

## Asset workflow

Runtime assets are the three files under `assets/data/` named above, plus `assets/fonts/KFGQPCNastaleeq-Regular.ttf`, `assets/fonts/AlQuranIndoPak.ttf`, splash images, `assets/reciters/`, `assets/flags/`, and `assets/azan-audio/`. When more than one on-screen translation is selected, each ayah’s credit label is drawn smaller than the translation body.

`tool/split_quran_json.py` writes `assets/data/surahs/NNN.json` from the colored file. The reader does not open those slices. `tool/smoke_sqlite.dart` checks that app 1:1 maps to the database row `DbAyah` expects. None of that is bundled as a reader source.
